# SatLoc – מסמך תכנון

> תצוגת כדור הארץ מהחלל (בסגנון Google Earth) עם לוויינים בזמן אמת, בדגש על לווייני ISI (ImageSat International).
> אפליקציה להתקנה: דסקטופ קודם, אנדרואיד אחר כך.
>
> מסמך זה הוא תוצר שלב "החשיבה המעמיקה". הוא חי: כל החלטה שמשתנה מתעדכנת כאן.

## 1. מטרה והיקף גרסה 1

**חוויית המשתמש בגרסה 1:**

1. פותחים את האפליקציה ורואים את כדור הארץ מהחלל: תמונות לוויין, אטמוספירה, כוכבים, וקו היום/לילה נכון לשעה הנוכחית.
2. לוויין ISI הפעיל (EROS-C3) מסומן ונע בזמן אמת; לוויינים נוספים מצטרפים דרך הקטלוג.
3. לחיצה על לוויין פותחת פאנל פרטים: גובה, מהירות, קו רוחב/אורך, זמן הקפה, גיל נתוני המסלול, ומפעילה: מעקב מצלמה, קו מסלול, ground track, footprint, ורצועת צילום (swath).
4. שליטה בזמן: play/pause, הרצה מהירה קדימה ואחורה, קפיצה לתאריך, וחזרה ל"עכשיו".
5. חיפוש והוספה של כל לוויין מקטלוג CelesTrak (תחנת החלל, GPS, Starlink, לוויינים ישראליים ועוד).
6. חיזוי מעברים: בוחרים מיקום (לחיצה על הגלובוס / GPS / ישראל כברירת מחדל) ומקבלים את המעברים ב-48 השעות הקרובות, עם קפיצה בזמן למעבר.

**מחוץ להיקף גרסה 1:** תלת-ממד פוטוריאליסטי של Google, משתמשים והרשאות, שרת, iOS, מודלים תלת-ממדיים מפורטים של לוויינים, נתוני Space-Track (דורש התחברות).

### 2.3 אילוצים טכניים שנמצאו

- **Cesium ≥ 1.140 דורש WebGL 2** (או WebGL 1 עם הרחבת instancing) לתוויות ואייקונים. WebView2 ב-Windows, WKWebView ב-macOS ו-Android WebView תומכים. זה **לא** דורש התאמה מצידנו, רק מודעות.
- **Tauri על Linux** משתמש ב-WebKitGTK, שיש לו בעיות WebGL מתועדות (ביצועים, הקשרים שאובדים, במיוחד עם NVIDIA). Tauri מתעדים עקיפות. אם הדסקטופ העיקרי הוא Linux, נשקול מעטפת Electron לדסקטופ (ראו 3.3).
- **Tauri על אנדרואיד**: מינימום Android 7.0 (SDK 24), משתמש ב-WebView של המערכת (מבוסס Chromium, מתעדכן דרך Play). בפועל נכוון ל-Android 9+.
- **CelesTrak חוסם runners של GitHub Actions** (הבקשות נכשלות ברמת הרשת). ה-workflow של ה-snapshot נופל אוטומטית למראה TLE ציבורי (tle.ivanstanojevic.me) שמפרסם את נתוני CelesTrak כ-JSON. האפליקציה עצמה מנסה CelesTrak קודם (מהמחשב שלך זה אמור לעבוד) ואז את המראה.
- **CelesTrak** מספק נתוני מסלול בפורמט OMM JSON דרך `gp.php` (למשל `?CATNR=54880&FORMAT=json`, `?GROUP=active&FORMAT=json`, `?NAME=EROS&FORMAT=json`). קבוצת `active` מכילה כ-12,000 עצמים. CelesTrak מבקשים לא למשוך את אותם נתונים יותר מפעם בשעתיים.
- **סביבת הפיתוח המרוחקת (הסשן הזה)** חוסמת גישה ל-celestrak.org, לשרתי התמונות (Esri, NASA GIBS, OSM) ול-space-track.org. GitHub ו-npm פתוחים. המשמעות: כאן אפשר לבנות, להריץ בדיקות יחידה, ולצלם את הגלובוס עם תמונות Natural Earth II המובנות. **משיכת TLE חיה ותמונות מקוונות נבדקות על המחשב שלך.**

## 3. ארכיטקטורה

### 3.1 העיקרון: ליבת web, מעטפת דקה

```
┌──────────────────────────────────────────────────────────┐
│                     Tauri 2 shell (Rust)                 │
│   http (בלי CORS) · fs / store (מטמון) · notifications   │
│   ─────────────── WebView של המערכת ───────────────────  │
│  ┌────────────────────────────────────────────────────┐  │
│  │              ליבת web (React + TS + Vite)          │  │
│  │                                                    │  │
│  │  ui/        פאנלים, חיפוש, ציר זמן, הגדרות         │  │
│  │  viewer/    Cesium: גלובוס, שכבות, רינדור לוויינים │  │
│  │  state/     zustand: בחירה, זמן, קטלוג, הגדרות     │  │
│  │  core/      TS טהור: TLE, SGP4, מעברים, גאומטריה   │  │
│  │  workers/   propagation worker (קטלוג גדול)        │  │
│  │  platform/  http · storage · notify (Tauri/דפדפן)  │  │
│  └────────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────────┘
```

- `core/` לא יודע על DOM, על React או על Cesium. הוא נבדק ביחידות ורץ גם ב-worker.
- `platform/` הוא הנקודה היחידה שיודעת אם רצים בתוך Tauri או בדפדפן. בדפדפן: `fetch` (דרך proxy של Vite בפיתוח) ו-IndexedDB. ב-Tauri: plugin-http (Rust, בלי CORS) ו-plugin-store/fs.
- שלושת מצבי ההרצה מאותו קוד: `npm run dev` (דפדפן), `npm run tauri dev` (חלון דסקטופ), `npm run tauri android dev` (טלפון).

### 3.2 למה Tauri 2 ולא Electron

| | Tauri 2 | Electron |
|---|---|---|
| אנדרואיד | כן, מאותו פרויקט | לא (צריך מעטפת שנייה, למשל Capacitor) |
| גודל התקנה | ~10 MB + נכסי Cesium | ~150–200 MB |
| WebGL | תלוי ב-WebView של המערכת (מצוין ב-Windows/macOS/Android, בעייתי ב-Linux) | Chromium מובנה, אמין בכל מקום |
| צד native | Rust (HTTP בלי CORS, קבצים, התראות) | Node |
| בשלות | דסקטופ יציב; מובייל חדש יותר אך production-ready | ותיק מאוד |

ההכרעה: Tauri 2, בגלל היעד של אנדרואיד. הסיכון היחיד המשמעותי הוא Linux, והוא נפתר על ידי הפרדת הליבה מהמעטפת.

### 3.3 מסלול נסיגה

אם WebGL במעטפת Tauri יתגלה כבעייתי על המחשב שלך, מוסיפים מעטפת Electron לדסקטופ בלבד (יום עבודה: `platform/` מקבל מימוש שלישי). הליבה, הרינדור וה-UI לא משתנים. אנדרואיד נשאר ב-Tauri.

## 4. הגלובוס (Cesium)

### 4.1 הגדרת ה-Viewer

- `baseLayer` מוגדר במפורש (בלי Cesium Ion, בלי טוקן).
- כוכבים (`skyBox`), אטמוספירה (`skyAtmosphere`, `showGroundAtmosphere`), שמש וירח.
- `globe.enableLighting = true`: תאורה לפי מיקום השמש בזמן הסימולציה. זה נותן את קו היום/לילה (terminator) בחינם, והוא זז עם ציר הזמן.
- ווידג'טים מובנים בגרסה 1: `Timeline` + `Animation` (play/pause/מהירות). מעוצבים מחדש לערכת נושא כהה. שאר הווידג'טים (geocoder, base layer picker, home) כבויים; מחליפים אותם ב-UI שלנו.
- פני שטח: אליפסואיד (שטוח). מהחלל זה לא נראה, ופני שטח עולמיים דורשים טוקן Ion. אם יוזן טוקן, מפעילים `CesiumTerrainProvider` של Cesium World Terrain.

### 4.2 אסטרטגיית תמונות (imagery)

| שכבה | מקור | מתי | הערות |
|---|---|---|---|
| ברירת מחדל | Esri World Imagery (`UrlTemplateImageryProvider`) | תמיד כשיש רשת | רזולוציה גבוהה עד רמת רחוב, הכי דומה ל-Google Earth. דורש ייחוס (attribution) ל-Esri ב-UI. לשימוש אישי/לא מסחרי. |
| חלופה 1 | NASA GIBS: Blue Marble (`WebMapTileServiceImageryProvider`, EPSG:4326) | לפי בחירה בהגדרות | מראה "חלל" יפה, חינמי לחלוטין, רזולוציה בינונית. |
| חלופה 2 | NASA GIBS: MODIS True Color יומי | לפי בחירה | עננים אמיתיים של אותו יום. פערים באזורי לילה/קטבים. |
| גיבוי | Natural Earth II (מובנה ב-Cesium, `Assets/Textures/NaturalEarthII`) | בלי רשת / כשל טעינה | רזולוציה נמוכה, אבל תמיד עובד. זה גם מה שרואים בבדיקות בסביבה המרוחקת. |
| אופציונלי | Cesium Ion (Bing + World Terrain) | אם הוזן טוקן בהגדרות | הטוקן נשמר מקומית ב-store של Tauri. |

לוגיקת מעבר: מנסים את שכבת ברירת המחדל; אם הטעינה נכשלת (למשל אין רשת), נופלים ל-Natural Earth II ומציגים חיווי "offline".

### 4.3 רינדור לוויינים בשתי שכבות (tiers)

**Tier 1: לוויינים נבחרים/מסומנים (יחידים עד עשרות)**
- `Entity` לכל לוויין, עם `CallbackProperty` למיקום (מחושב במדויק בכל פריים בתהליכון הראשי).
- תווית, אייקון, קו מסלול, ground track, footprint, רצועת swath (ראו פרק 6).
- לווייני ISI הם תמיד Tier 1.

**Tier 2: הקטלוג המוצג (מאות עד ~12,000)**
- `PointPrimitiveCollection` אחד, נקודה לכל לוויין. זה המבנה היעיל ביותר של Cesium לאלפי נקודות.
- מיקומים מתעדכנים בכל פריים מ-`Float64Array` שמגיע מה-worker.
- תוויות רק בריחוף עכבר או כשמוצגים פחות מ-200 לוויינים.
- לחיצה (`scene.pick`) על נקודה בוחרת אותה ומקדמת אותה ל-Tier 1.

בגרסה 1 (עד אבן דרך M4) החישוב של Tier 2 נעשה בתהליכון הראשי עם תקרה של ~500 לוויינים מוצגים. הממשק בין ה-viewer לחישוב כבר מוגדר כך שה-worker נכנס ב-M4 בלי לשנות את הרינדור.

## 5. זמן וחישוב מסלולים

### 5.1 מודל הזמן

- מקור האמת היחיד לזמן הוא `viewer.clock.currentTime` (זמן סימולציה). **שום חישוב לא קורא את שעון המערכת ישירות.**
- `clockRange = UNBOUNDED`, `multiplier` בין -1000 ל-1000 עם presets (1, 10, 60, 300, 1000), `shouldAnimate` = play/pause.
- כפתור "Now": מאפס לזמן המערכת ולמכפיל 1.
- כשמזיזים את הזמן רחוק מה-epoch של ה-TLE (מעל ~7 ימים) מוצגת אזהרת דיוק. SGP4 מדויק לכ-1 ק"מ סביב ה-epoch ומידרדר בכמה ק"מ ליום.

### 5.2 מ-TLE למיקום על הגלובוס

1. OMM JSON / TLE → `satrec` (satellite.js `json2satrec` / `twoline2satrec`).
2. `propagate(satrec, date)` → מיקום ומהירות במסגרת **TEME** (ק"מ).
3. TEME → מסגרת קבועה של כדור הארץ (ECEF) עם `gstime` + `eciToEcf` של satellite.js. **הוחלט ב-M1** לעשות את ההמרה ב-`core/` ולא עם המטריצה של Cesium, כדי שאותו קוד ישמש גם ב-worker ובחיזוי מעברים (שם אין Cesium). ההבדל בין שתי הדרכים קטן ממטרים.
4. הנקודה נכנסת ל-Cesium במסגרת ה-FIXED (ברירת המחדל של Cesium) אחרי המרה מק"מ למטרים, כך שהיא נראית במקום הנכון מעל הקרקע.

הערה על satellite.js 7: הספרייה שומרת ב-`satrec.no` את התנועה הממוצעת אחרי המרת Kozai→Brouwer (מה ש-SGP4 עובד איתו) ואת הערך המפורסם ב-`satrec.nokozai`. זמן ההקפה ו"סיבובים ליום" בממשק מחושבים מהערך המפורסם. הספרייה גם מייצאת מנוע WASM לחישוב מרובה (Bulk Propagation, פי 3 עד 12 מהיר יותר), שישמש אותנו ב-M4; ה-worker שלו דורש `worker.format = 'es'` ב-Vite.

למה לא להזין TEME ישירות למסגרת ה-INERTIAL של Cesium (כמו בדוגמאות ישנות): TEME אינו ICRF; ההבדל (נקיפה מאז 2000) מגיע לכ-0.3°, שהם עשרות ק"מ בגובה מסלול. גישת המטריצה חוסכת את השגיאה.

### 5.3 חלוקת עבודה בין תהליכון ראשי ל-worker (M4)

- ה-worker מחזיק את כל ה-`satrec`ים (פירוק 12,000 רשומות לוקח ~100ms, פעם אחת).
- בכל פריים התהליכון הראשי שולח `{ timeMs, ids }`; ה-worker מחזיר `Float64Array` של מיקום + מהירות (TEME) כ-transferable (בלי העתקה).
- התהליכון הראשי מתקן את הפיגור של פריים אחד עם המהירות: `pos + vel · (t_now − t_sample)`. במכפיל 1 הפיגור הוא ~120 מ', בלתי נראה. הלוויין הנבחר ממילא מחושב במדויק ב-Tier 1.
- תקרות: דסקטופ 12,000 נקודות; אנדרואיד 1,000–2,000 (הגדרה).

## 6. הפיצ'רים ואלגוריתמים

### 6.1 קו מסלול (orbit path)

- דוגמים הקפה אחת מלאה (זמן הקפה מתוך `satrec`, למשל ~95 דקות ל-EROS) ב-~360 נקודות **ב-TEME**, פעם אחת.
- בכל פריים מסובבים את כל הנקודות ב-GMST של הזמן הנוכחי (TEME→ECEF). התוצאה: אליפסה שקבועה במרחב האינרציאלי בעוד כדור הארץ מסתובב מתחתיה. זה בדיוק המראה של Google Earth / STK.
- מרעננים את הדגימה כשהזמן זז ביותר מחצי הקפה מנקודת הדגימה.

### 6.2 Ground track

- דוגמים זמנים מ-t−½ הקפה עד t+1 הקפה בצעדים של 10 שניות; לכל דגימה: TEME → Fixed (עם המטריצה של **אותו זמן**) → קו רוחב/אורך → נקודה בגובה 0.
- מצוירים כ-`polyline` על פני הקרקע. העבר בצבע עמום, העתיד בצבע מלא.

### 6.3 Footprint (כיסוי) ו-swath (רצועת צילום)

- **מעגל ראות (footprint):** הזווית המרכזית שבה הלוויין נראה מעל האופק בזווית גובה מינימלית ε:
  `λ = arccos( (R⊕ / (R⊕ + h)) · cos ε ) − ε`, רדיוס על הקרקע `d = R⊕ · λ`.
  ל-EROS (h≈500 ק"מ, ε=0): d ≈ 2,450 ק"מ. מצויר כ-`ellipse` על הקרקע במיקום תת-הלוויין, עם `CallbackProperty` לרדיוס.
- **רצועת צילום (swath):** רוחב קבוע פר לוויין מקובץ הפריסט (EROS-B: 7 ק"מ, EROS-C3: 11.5 ק"מ). מצוירת כ-`corridor` לאורך ה-ground track העתידי. זה מה שהלוויין יכול לצלם בנדיר; EROS גם מטה את הגוף לצילום מהצד, ולכן זו הערכה ולא רצועת המשימה בפועל.
- שני האלמנטים מופעלים בנפרד מהפאנל.

### 6.4 חיזוי מעברים

- קלט: מיקום צופה (lat, lon, alt), לוויין, חלון (ברירת מחדל 48 שעות), זווית גובה מינימלית (ברירת מחדל 10°).
- אלגוריתם (רץ ב-worker):
  1. צעד גס של 30 שניות: מחשבים זווית גובה עם `ecfToLookAngles`. 48 שעות = 5,760 חישובים ≈ 60ms ללוויין.
  2. מזהים מעברי חצייה של סף הגובה (עלייה/ירידה).
  3. מדייקים כל חצייה בחצייה בינארית לרזולוציה של שנייה; מוצאים את שיא הגובה בתוך המעבר.
  4. פלט לכל מעבר: זמן התחלה (AOS), שיא (TCA), סיום (LOS), גובה מרבי, אזימוט התחלה וסיום, משך.
- UI: רשימת מעברים; לחיצה מקפיצה את הסימולציה ל-AOS ומצלמת על המיקום. אופציונלי: התראת מערכת דקות לפני מעבר (plugin-notification).
- מיקום צופה: לחיצה על הגלובוס, GPS של המכשיר, או presets (ישראל/תל אביב כברירת מחדל). נשמר בין הרצות.

## 7. שכבת הנתונים

### 7.1 מקור

CelesTrak GP API, פורמט OMM JSON (חוסך פירוק TLE ומכיל שם, NORAD ID, מזהה בינלאומי ו-epoch):

- פריסט ISI: `gp.php?CATNR=29079&FORMAT=json`, `gp.php?CATNR=54880&FORMAT=json` (או `NAME=EROS`).
- קבוצות: `active`, `stations`, `visual`, `resource` (לווייני תצפית; EROS נמצא כאן), `gps-ops`, `galileo`, `starlink`, `weather`, `geo`, `cubesat` ועוד.
- ייבוא ידני של קובץ TLE (לשימוש לא מקוון או למקורות אחרים).

### 7.2 מטמון וריענון

- כל קבוצה נשמרת מקומית עם חותמת זמן (Tauri store / IndexedDB בדפדפן).
- בהפעלה: אם המטמון צעיר משעתיים משתמשים בו; אחרת מרעננים ברקע ומציגים בינתיים את הישן.
- בזמן ריצה: ריענון כל שעתיים (בהתאם לבקשת CelesTrak).
- לכל לוויין מוצג "גיל ה-TLE" (ימים מה-epoch). מעל 7 ימים: אזהרה. מעל 30: סימון "לא אמין".
- **Snapshot מובנה:** הבנייה כוללת קובץ `src/data/isi-snapshot.json` עם נתוני EROS-B/C3 עדכניים, כך שהפעלה ראשונה ללא רשת מציגה משהו, ובדיקות היחידה דטרמיניסטיות. סקריפט `scripts/update-snapshot.mjs` מעדכן אותו (רץ על המחשב שלך או ב-GitHub Action, לא בסביבה המרוחקת החסומה).

### 9.1 פרטים טכניים שכדאי לדעת מראש

- **נכסי Cesium:** Cesium צריך את התיקיות `Workers`, `ThirdParty`, `Assets`, `Widgets` בזמן ריצה. מעתיקים אותן ל-`dist/cesium` ומגדירים `CESIUM_BASE_URL`. ב-Tauri הן מוגשות מהאפליקציה עצמה.
- **CSP של Tauri:** צריך להתיר `connect-src` ו-`img-src` לשרתי התמונות ול-CelesTrak, `worker-src blob:` ל-workers של Cesium, ו-`data:`/`blob:` לתמונות. מכוונים ב-M0 ומתעדים.
- **Workers תחת פרוטוקול מותאם** (`tauri://` ב-macOS/Linux): Tauri 2 תומך; זה סעיף אימות מפורש ב-M0.
- **תאורת יום/לילה:** Cesium מערבב את הצללת הלילה רק כשהמצלמה רחוקה מפני השטח (`lightingFadeOutDistance` / `lightingFadeInDistance`), כדי שמפות יישארו קריאות בלילה. אנחנו מסתכלים מהחלל, אז קובעים 0 ו-1 מטר: קו הטרמינטור מצויר בכל גובה. אומת בצילומי מסך ב-00:00, 06:00 ו-12:00 UTC מול מיקום השמש המחושב.
- **הגדרות** נשמרות ב-`tauri-plugin-store` (קובץ JSON בתיקיית האפליקציה). הטוקן של Ion נשמר שם כטקסט; זה טוקן אישי בהיקף קריאה, מקובל.

## 10. בנייה, CI והפצה

- **`ci.yml`** (על כל push/PR): typecheck, vitest, `vite build`, בדיקת Playwright עם צילום מסך, `cargo clippy` למעטפת על Ubuntu, ובנוסף **`tauri build` על Windows** שמעלה את קובץ ההתקנה (.exe/.msi) כ-artifact של הריצה. כך כל push מייצר קובץ התקנה להורדה מלשונית Actions, בלי לתייג גרסה.
- **`release.yml`** (על תג `v*`): `tauri-apps/tauri-action` במטריצה:
  - `windows-latest` → `.msi` + `.exe` (NSIS)
  - `macos-latest` → `.dmg` (Apple Silicon + Intel)
  - `ubuntu-22.04` → `.AppImage` + `.deb`
  התוצרים עולים ל-GitHub Release אוטומטית.
- **חתימה:** בלי חתימה, Windows יציג אזהרת SmartScreen ו-macOS ידרוש "Open anyway". לשימוש אישי זה סביר; חתימה (תעודה) היא שדרוג עתידי. עדכון אוטומטי (`plugin-updater`) נכנס אחרי שיש חתימה.
- **פיתוח מקומי (על המחשב שלך):** דרישות Tauri: Rust, ו-WebView2 (מגיע עם Windows 10/11). `npm run tauri dev` פותח את האפליקציה עם hot reload.

## 11. אנדרואיד (M7): מה משתנה ומה לא

**לא משתנה:** הליבה, הרינדור, ה-UI (מלבד פריסה), נתוני הקטלוג, המטמון.

**משתנה:**
- `npm run tauri android init` יוצר את פרויקט האנדרואיד. דרישות: Android Studio, SDK, NDK, JDK 17, יעדי Rust ל-ARM.
- פריסה למסך צר: bottom sheet במקום סרגל צד, כפתורים גדולים, מחוות מגע (Cesium תומך במגע כברירת מחדל).
- פרופיל ביצועים: תקרת 1,000–2,000 לוויינים מוצגים, `maximumScreenSpaceError` גבוה יותר לתמונות, אטמוספירת קרקע כבויה. Cesium צורך מאות MB זיכרון; מכשירי ביניים ומעלה.
- GPS למיקום הצופה דרך plugin-geolocation.
- בנייה ב-CI: `tauri android build --apk` על Ubuntu עם SDK/NDK; חתימת APK עם keystore (סוד ב-GitHub).
- מינימום: Android 9+, WebView מעודכן (WebGL 2).

## 12. בדיקות

- **יחידה (vitest, `core/`):**
  - SGP4 מול ערכי ייחוס ידועים (מקרי הבדיקה של satellite.js / Vallado).
  - TEME→Fixed: לוויין גיאוסטציונרי חייב לשמור קו אורך קבוע לאורך זמן.
  - footprint: ערכים ידועים (h=500 ק"מ, ε=0 → ~2,450 ק"מ).
  - מעברים: בתוך כל מעבר זווית הגובה מעל הסף; AOS/LOS מדויקים לשנייה; אין מעברים חופפים.
  - קטלוג: פירוק OMM, גיל TLE, חיפוש.
- **Smoke (Playwright, Chromium):** האפליקציה בדפדפן עולה, הגלובוס מצויר (עם Natural Earth II), לחיצה על EROS-C3 פותחת פאנל. רץ גם בסביבה המרוחקת עם צילומי מסך.
- **ידני על המחשב שלך:** TLE חי מ-CelesTrak, תמונות מקוונות, השוואת מיקום EROS-C3 מול n2yo/CelesTrak, Tauri build.
